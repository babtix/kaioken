The module centers around a `run` struct (wiki.go) that orchestrates the pipeline: code scanning (`scan.Repo`), indexing (`codemap.Build`), global outlining (`planOutline`), per-section planning (`planSection`), and document generation (`generateDoc`). Supporting components include: `brief.go` manages a shared architecture brief injected into every chapter prompt; `facts.go` extracts framework-specific facts (routes, models, commands, env) via regex and codemap, cached per repository root; `graph.go` builds a visualization graph of the generated wiki containing document, file, and section nodes with contains/links/source edges; `provenance.go` appends/parses a machine-readable footer listing source files per document for incremental updates; `verify.go` checks documents for hallucinated claims against the code index; `polish.go` post-processes documents to sanitize invalid Mermaid diagrams and insert cross-links between chapters; `update.go` performs incremental updates by comparing against a baseline commit (`Stamp`), revising only affected documents; `estimate.go` predicts token and call costs for a wiki run. Data flows from source scan → index → outline → section plans → documents → provenance/footer → verification → polishing. Error handling propagates errors upward; caching avoids redundant fact extraction; concurrency is limited by `errgroup` to prevent rate limits.
