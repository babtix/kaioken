The module consists of Go files in internal/wiki/ that collaborate through a defined pipeline. wiki.go orchestrates the process: Run() indexes code structure via codemap.Build(), loads or creates a wiki outline (OutlinePath), generates a shared architecture brief (loadOrBuildBrief in brief.go), then processes sections in parallel. Each section runs a sub-plan, generates documents (with critique/correction passes if multiplier >=4 via passes.go), and applies post-processing (polish.go). Provenance tracking (provenance.go) stamps source files in documents for incremental updates (update.go), which revises only documents affected by git diffs using the stored baseline (Stamp). Verification (verify.go) checks documents for hallucinations against the code index. Data flows from code scan → indexing → planning → brief → section processing → document generation → polishing → provenance stamping → optional update/verification. Key mechanisms: mutex-protected facts cache (detectFacts in facts.go), provenance footers for change detection, and errgroup-bounded concurrency for parallel section processing.
