The system consists of two primary components: the skill generation orchestrator (in internal/skills/generate.go) and the skill data model and persistence layer (in internal/skills/skills.go). The orchestrator (Run function) begins by building a code map from scanned repository files, then uses an LLM to propose relevant skills based on the repository's layout, manifests, and code structure. For each proposed skill, it checks for existing skills (unless forced to regenerate), generates the skill content in a concurrent goroutine (limited by config.EffectiveConcurrency), saves the skill to disk, and updates a shared list of successfully written skills. After all skills are processed, it refreshes the skill index (README.md in the skills directory) and updates the AGENTS.md file to point to the new skills. The skill data model (Skill struct) includes metadata such as name, description, source files, generation timestamp, and origin, with methods to render the skill as a YAML-frontmatter markdown file, save it to disk, and load or parse existing skill files. Error handling is designed to be resilient: individual skill generation failures are logged but do not halt the entire process, and malformed skill files are skipped during listing without affecting other skills.
