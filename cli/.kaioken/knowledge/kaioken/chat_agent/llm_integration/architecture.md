The module centers around the `Client` struct in `openrouter.go`, which holds configuration (API key, base URL, model, etc.) and an HTTP client. The `Providers` map registers built-in providers, each specifying base URL, API key environment variable, custom auth header (if needed), protocol (e.g., 'anthropic' for Anthropic), and whether a base URL override is required. `NewForProvider` constructs a `Client` for a given provider, applying overrides and validating the API key (skipping for local providers). Requests are sent via methods like `Chat` and `ChatWithToolsStream`, which build request bodies (with max_tokens, temperature, tools) and send them to the provider. The client handles retries for transient errors (using exponential backoff) and specifically treats 402 errors by learning an affordability ceiling from the provider and retrying with reduced max_tokens. Authentication is provider-specific: most use 'Authorization: Bearer <key>', but Anthropic uses 'x-api-key' and Azure uses 'api-key'. For Anthropic, `anthropic.go` translates Kaioken's OpenAI-shaped messages into Anthropic's Messages API format (top-level system field, content blocks). Usage tracking is performed by `recordUsage`, updating tokens, cost, and cache hits with mutex protection. Streaming is supported via `ChatStream` and `ChatWithToolsStream`, which parse server-sent events (SSE) and handle provider-specific formats while assembling messages and tool calls from deltas. Local providers (Ollama, LM Studio, etc.) are handled in `local.go`, where `NewLocal` creates a client without an API key and with a longer timeout (30 minutes).
