The module centers around the Client struct in openrouter.go, which holds configuration (API key, base URL, model) and state (usage counters, budget cap). The global Providers map (openrouter.go) defines provider-specific settings like BaseURL, KeyEnv, AuthHeader, and Protocol. Authentication varies per provider: Anthropic uses 'x-api-key' header, Azure uses 'api-key', others use 'Authorization: Bearer'. Protocol selection (openrouter.go) determines wire format: OpenAI-compatible chat/completions by default, or Anthropic's native Messages API (handled in anthropic.go). Key mechanisms include: retries via retry.go (honoring Retry-After headers with fallback backoffs), token budgeting via budget.go (reducing max_tokens on 402 errors using affordableTokens), usage tracking via recordUsage (openrouter.go) accumulating tokens and cost with separate handling for OpenAI-style (cached tokens in prompt_tokens) and Anthropic-style (cache traffic reported separately), streaming via stream.go (SSE parsing for both protocols with fallback to non-streaming), local model support via local.go (Ollama, etc. without API key), and reasoning levels via thinking.go (translating Thinking field to provider-specific parameters like reasoning_effort or thinking.budget_tokens). Data flow: requests are built with thinking/usage accounting, sent via HTTP, responses parsed for content/tool calls, with errors checked for retriability (429/5xx) or handled per provider-specific logic (e.g., NVIDIA model-specific URL fallback in stream.go).
