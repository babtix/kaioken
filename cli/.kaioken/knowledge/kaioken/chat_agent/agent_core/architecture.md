The module consists of multiple Go files in internal/agent. The main loop is in agent.go (Agent.Run), which drives the tool-calling cycle. It depends on budget.go for proactive cost guardrails (BudgetGuard), compact.go for conversation compaction, context.go for building the system prompt from sources (identity, tools, mode, model, knowledge), diff.go for approval previews, knowledge.go for documentation catalog, mode.go for agent modes, prompts.go for per-model guidance, prune.go for pruning old tool results, reminders.go for applying mode-specific reminders, task.go for sub-agent delegation, todo.go for todo list, and tools.go for Agent struct and tool implementations (read_file, write_file, etc.). Data flow: Run loop applies reminders, checks budget, gets model response via chat, executes tool calls, feeds results back until final answer or step limit. Error handling includes budget hard stops, context cancellation, and tool execution failures. The agent confines file operations to the repository root and uses a UI interface for all user interactions.
