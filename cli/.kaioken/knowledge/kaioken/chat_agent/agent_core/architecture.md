The module consists of multiple Go files in internal/agent. The main loop is in agent.go (Agent.Run), which drives the tool-calling cycle. It depends on budget.go for proactive cost guardrails (BudgetGuard), compact.go for conversation compaction (which now uses fileops.go to track read and modified files across turns), context.go for building the system prompt from sources (identity, tools, mode, model, knowledge), diff.go for approval previews, knowledge.go for documentation catalog, mode.go for agent modes, prompts.go for per-model guidance, prune.go for pruning old tool results, reminders.go for applying mode-specific reminders, task.go for sub-agent delegation, todo.go for todo list, and tools.go for Agent struct and tool implementations (read_file, write_file, etc.). Additionally, editmatch.go provides fuzzy matching for the edit_file tool to handle variations in whitespace, quotes, and line endings; epoch.go implements ContextEpoch for tracking context changes and generating mid-conversation system updates; events.go defines typed agent events and EventsUI for emitting events to decouple the agent from UI specifics; tool_store.go implements bounding of tool output (truncation and spilling to disk) to manage large outputs; fileops.go provides cumulative file tracking for compaction summaries; retry.go handles agent-level retries for transient failures (e.g., network errors); tool_executor.go executes tool calls, grouping concurrent read-only tools and sequential execution for others, with hook points for interception; tool_registry.go allows dynamic registration of tools at runtime; and the events package is split into events/types.go (defining lifecycle event types) and events/bus.go (implementing the event bus for internal hooks). Data flow: Run loop applies reminders, checks budget, gets model response via chat, executes tool calls (via tool_executor.go, which uses the tool registry and hooks), feeds results back until final answer or step limit. Error handling includes budget hard stops, context cancellation, and tool execution failures. The agent confines file operations to the repository root and uses a UI interface for all user interactions.
