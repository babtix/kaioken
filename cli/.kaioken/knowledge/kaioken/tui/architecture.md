The tui module follows the Model-View-Update (MVU) pattern from Bubble Tea. The central state is held in the Model struct (defined in tui.go), which includes the repository path, configuration, LLM client, and UI state. User input is processed in the Update method, which handles messages such as user keystrokes, asynchronous operation results (e.g., from impact prediction or web research), and internal events. The View method constructs the UI by combining a sticky header (logo and status panel, from logo.go), the transcript viewport, the composer, and the command palette (from palette.go). Slash commands are registered in commands.go and matched via the filterCommands function; the dispatch method in tui.go routes commands to specific handlers (e.g., doExt for extension management, doImpact for impact prediction). Long-running operations like impact prediction (startImpact in impact.go) and web research (startResearch in research.go) are executed in goroutines, communicating results via channels on m.events. Error handling is done by sending doneMsg with an error, which is then displayed in the transcript using errStyle.
