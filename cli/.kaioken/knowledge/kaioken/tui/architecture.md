The TUI is centered around the `Model` struct in `tui.go`, which holds application state including repository configuration, LLM client, conversation history, agent mode, undo stack, and UI components (viewport, input, spinner, list). User input is processed via the `dispatch` function, which routes slash commands to specific handlers (e.g., `doExt` for /ext, `startImpact` for /impact) or initiates a chat turn with the agent via `startChat`. The agent runs in a goroutine and communicates results through channels: `events` for logging, `approvals` for request approvals, and `agentDoneMsg` for completed turns.

The view is constructed by combining a sticky header (showing logo and live status from `welcomeBanner` and `statusPanel`), a viewport displaying the transcript and live assistant text (with markdown rendering via `glamour.TermRenderer` in `markdown.go`), and a composer input field. The command palette (from `palette.go`) appears above the composer when a slash is typed, offering autocomplete for registered commands. The TUI uses Bubble Tea components for UI elements and handles terminal resizing to adjust layout.

The impact prediction feature: The `/impact <description>` command triggers impact analysis via `startImpact` in `impact.go`. It validates input, checks for LLM client, and runs a background goroutine to scan the repository (`scan.Repo`) and execute impact prediction (`impact.Run`). Results are sent via channels: `events` for progress/logging, `impactMsg` for the report. Upon receiving `impactMsg`, the TUI switches to `modeImpact` by calling `openImpactTree` (from `impacttree.go`), which displays an interactive tree view. The impact tree (`impactTree` struct) allows filtering by kind (symbols, files, etc.), collapsing/expanding groups, and navigation. Closing the tree (via `q`, `esc`, etc.) appends the report to the transcript via `closeImpactTree`.

Authentication: API keys are managed per provider in the session (`apiKeys` map) and persisted globally via `/key` command (stored in `~/.kaioken/config.yaml`). Caching: The markdown renderer is cached per terminal width, and extension tools are cached via `ext.CachedTools`. Error handling: Errors are displayed using `errStyle` (red) and logged via `logMsg`; async operations use `doneMsg` to convey success or failure. Dependency direction: The TUI depends on internal packages (agent, llm, config, etc.) but does not expose its internals to them, maintaining a unidirectional dependency flow from UI to business logic.
