# generate-wiki-documentation
Run `kaioken wiki` to generate the wiki documentation for the repository. This command scans the repository, plans the wiki outline, and generates multi-pass wiki documentation including section documents and subsection documents.

## Prerequisites
The repository must be configured for Kaioken (i.e., have a `.kaioken` directory with config) and the LLM API key must be set via environment variable (e.g., `OPENROUTER_API_KEY`) or in the global Kaioken config.

## Steps
1. Ensure you are in the root directory of the repository.
2. Run the command: `kaioken wiki`
   - To override the default depth multiplier (×3), pass a multiplier like `x2` or `x4` as an argument (e.g., `kaioken wiki x2`).

## Conventions to follow
- The command uses the current directory as the target repository by default; use `-repo <path>` to specify a different repository.
- The multiplier argument must be in the format `xN` where N is an integer between 1 and 10.
- The command will reuse an existing wiki outline (`.kaioken/wiki_plan.yaml`) unless `-force` is used to re-plan the outline.
- Output is written to `.kaioken/wiki/` directory; the main wiki document is `.kaioken/wiki/README.md`.

## Verification
Check that the wiki documentation was generated successfully:
1. Verify the command completes without error and outputs a success message like `wiki done in <time> → .kaioken/wiki/README.md`.
2. Confirm the file `.kaioken/wiki/README.md` exists and has non-zero size.
3. Optionally, check that subsection documents exist in their respective section directories under `.kaioken/wiki/`.

## Common mistakes
- Forgetting to set the LLM API key, causing the command to fail during LLM client initialization with an authentication error.
- Running the command from a subdirectory without specifying `-repo`, resulting in the wiki being generated for the subdirectory instead of the repository root.
- Using an invalid multiplier format (e.g., `2` instead of `x2`) which is ignored and defaults to ×3.
- Expecting the command to update module-based knowledge cards (generated by `kaioken generate`); the `wiki` command generates a separate documentation set.
