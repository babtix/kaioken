The agent operates in a turn-based loop driven by the Run method in agent.go. Each turn involves calling the LLM (via llm.Client), executing requested tools (with parallel execution for read-only tools and sequential for others), and processing results. Context is managed via pruning (removing old tool results) and compaction (summarizing conversation) to stay within the model's context window, implemented in prune.go and compact.go. The agent uses an event bus (events.Bus) for lifecycle events (turn start/end, tool calls, approvals) allowing observers to hook into the run. Permissions are governed by mode (ModeBuild, ModePlan, etc.) and a ruleset (permission.go) for standing approvals. Sub-agents are created via the delegate (writable) and task (read-only) tools, with isolated context and worktree. The system prompt is assembled from multiple sources (identity, tools, mode, model, knowledge, guidelines, project instructions, memory, user notes) in context.go. Tool output is bounded and spilled to disk (tool_store.go) to prevent context bloat. The agent guards against excessive spending with BudgetGuard (budget.go) and provides reminders (reminders.go) that are reapplied each turn to reinforce constraints.
