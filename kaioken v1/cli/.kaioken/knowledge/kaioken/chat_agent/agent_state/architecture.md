The session package provides durable conversation storage via Session structs persisted as JSONL files (v2 format) or legacy JSON. Sessions support branching through ForkAt and ForkBack operations, with tree structure maintained in Entries and Leaf fields to preserve history during compaction or retries. State management occurs through internal/state's State struct mapping module names to ModuleState containing SHA256 hashes of source files, enabling incremental regeneration by comparing current hashes against stored values. Data flow involves loading sessions via Load, modifying in-memory state (Record, AdmitInput, etc.), and persisting changes via Save/SaveForce. The state package is loaded at update start, consulted to skip unchanged modules, and saved after processing. Dependencies flow: session → llm/config; state → config/scan; no direct session-state coupling.
