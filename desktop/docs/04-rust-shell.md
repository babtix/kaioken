# 04 — The Rust shell (`src-tauri`)

Target: **Tauri v2.10.x** (2.10.1 was current in March 2026). If the installed
version's API differs, follow the installed docs and record the drift in
`09-risks.md`.

The Rust layer does four things: spawn the sidecar, read its handshake, supervise
it, and hand the front-end a port and token. Roughly 400 lines total. Resist
adding `#[tauri::command]`s for engine features — those belong in the daemon.

Notes an implementing agent must not skip:

- **`connect-src` needs the loopback wildcard.** Without
  `http://127.0.0.1:*` every `fetch` to the daemon is blocked by CSP with a
  console error that looks like a network failure. The port wildcard is valid CSP
  host-source syntax.
- **`style-src 'unsafe-inline'`** is required by Tailwind's runtime-injected
  styles and by mermaid's generated SVG styling. It is scoped to `'self'`
  otherwise.
- **`visible: false`** plus an explicit `show()` after the handshake avoids the
  white-flash-then-error sequence when the sidecar fails to start.
- Dev server port is **1420**, the Tauri convention. Set it in `vite.config.ts`
  (`server: { port: 1420, strictPort: true }`) — `strictPort` matters, because a
  silent fallback to 1421 breaks `devUrl`.

The sidecar is spawned from **Rust**, not JavaScript, so the front-end never gets
shell permissions. The `args` allow-list is deliberately exact: the only variable
part is the port digits.

## 4.5 `src/daemon.rs`

```rust
use std::sync::Mutex;
use tauri::{AppHandle, Manager};
use tauri_plugin_shell::{process::{CommandChild, CommandEvent}, ShellExt};

#[derive(Clone, serde::Serialize)]
pub struct DaemonInfo {
    pub port: u16,
    pub token: String,
    pub version: String,
}

pub struct DaemonState {
    pub info: Mutex<Option<DaemonInfo>>,
    pub child: Mutex<Option<CommandChild>>,
}

/// Spawn the sidecar and wait for its one-line JSON handshake.
///
/// The token is generated here and written to the child's stdin rather than
/// passed on the command line, so it never appears in a process listing. The
/// same stdin pipe doubles as the child's death-watch: when this process exits,
/// the pipe closes, the daemon reads EOF and shuts itself down.
pub async fn start(app: &AppHandle) -> anyhow::Result<DaemonInfo> {
    let token: String = {
        use rand::Rng;
        let bytes: [u8; 32] = rand::thread_rng().gen();
        bytes.iter().map(|b| format!("{b:02x}")).collect()
    };

    let (mut rx, mut child) = app
        .shell()
        .sidecar("kaioken-daemon")?
        .args(["daemon", "--port", "0", "--token-stdin"])
        .spawn()?;

    child.write(format!("{token}\n").as_bytes())?;

    // Handshake with a 10 s ceiling. Anything on stderr in that window is
    // captured so a failure can be shown to the user verbatim.
    let mut stderr_tail = String::new();
    let deadline = tokio::time::Instant::now() + std::time::Duration::from_secs(10);

    loop {
        let ev = tokio::time::timeout_at(deadline, rx.recv()).await;
        match ev {
            Err(_) => anyhow::bail!("daemon did not report a port within 10s\n{stderr_tail}"),
            Ok(None) => anyhow::bail!("daemon exited during startup\n{stderr_tail}"),
            Ok(Some(CommandEvent::Stdout(line))) => {
                let text = String::from_utf8_lossy(&line);
                if let Ok(v) = serde_json::from_str::<serde_json::Value>(text.trim()) {
                    if v.get("kaioken_daemon").is_some() {
                        let info = DaemonInfo {
                            port: v["port"].as_u64().unwrap_or(0) as u16,
                            token: token.clone(),
                            version: v["version"].as_str().unwrap_or("?").to_string(),
                        };
                        // Keep draining stdout/stderr into the log; a full pipe
                        // would otherwise block the daemon mid-run.
                        tauri::async_runtime::spawn(async move {
                            while let Some(ev) = rx.recv().await {
                                match ev {
                                    CommandEvent::Stderr(b) => log::info!("daemon: {}", String::from_utf8_lossy(&b)),
                                    CommandEvent::Terminated(t) => { log::warn!("daemon exited: {t:?}"); break }
                                    _ => {}
                                }
                            }
                        });
                        app.state::<DaemonState>().child.lock().unwrap().replace(child);
                        return Ok(info);
                    }
                }
            }
            Ok(Some(CommandEvent::Stderr(b))) => {
                stderr_tail.push_str(&String::from_utf8_lossy(&b));
                if stderr_tail.len() > 4000 { stderr_tail.drain(..2000); }
            }
            Ok(Some(CommandEvent::Terminated(t))) => {
                anyhow::bail!("daemon exited with {t:?}\n{stderr_tail}")
            }
            _ => {}
        }
    }
}

pub fn stop(app: &AppHandle) {
    if let Some(child) = app.state::<DaemonState>().child.lock().unwrap().take() {
        let _ = child.kill();
    }
}
```

**Draining the pipes is not optional.** A daemon that writes a few megabytes of
stderr during a long wiki run will block on a full pipe if nobody reads it, and
the symptom — a run that freezes at 60% — looks nothing like the cause.

### Supervision

`lib.rs` owns a small restart policy: if `CommandEvent::Terminated` arrives while
the app is running, emit a Tauri event `daemon://down`, then retry `start()` up to
3 times with 1 s / 3 s / 9 s backoff. On success emit `daemon://up` with the new
`DaemonInfo`; the front-end re-reads it and re-subscribes. After three failures,
emit `daemon://dead` and let the front-end show the fatal error screen.

## 4.6 `src/commands.rs`

Exactly four commands. Anything else is a smell.

```rust
#[tauri::command]
fn daemon_info(state: tauri::State<DaemonState>) -> Result<DaemonInfo, String>;

/// Native folder picker for "Open repository".
#[tauri::command]
async fn pick_folder(app: AppHandle, title: String) -> Result<Option<String>, String>;

/// Reveal a file in Explorer / Finder / the desktop file manager.
#[tauri::command]
fn reveal_path(app: AppHandle, path: String) -> Result<(), String>;

/// Open a URL in the user's real browser, never in the WebView.
#[tauri::command]
fn open_external(app: AppHandle, url: String) -> Result<(), String>;
```

`open_external` must reject anything that is not `http://` or `https://` — a
generated wiki could contain a `file://` or custom-scheme link, and a document is
untrusted input.

## 4.7 `src/lib.rs`

```rust
#[cfg_attr(mobile, tauri::mobile_entry_point)]
pub fn run() {
    tauri::Builder::default()
        .plugin(tauri_plugin_shell::init())
        .plugin(tauri_plugin_dialog::init())
        .plugin(tauri_plugin_opener::init())
        .plugin(tauri_plugin_os::init())
        .plugin(tauri_plugin_process::init())
        .plugin(tauri_plugin_log::Builder::new().build())
        .manage(DaemonState { info: Mutex::new(None), child: Mutex::new(None) })
        .invoke_handler(tauri::generate_handler![
            daemon_info, pick_folder, reveal_path, open_external
        ])
        .setup(|app| {
            let handle = app.handle().clone();
            tauri::async_runtime::spawn(async move {
                match daemon::start(&handle).await {
                    Ok(info) => {
                        handle.state::<DaemonState>().info.lock().unwrap().replace(info.clone());
                        let _ = handle.emit("daemon://up", info);
                    }
                    Err(e) => { let _ = handle.emit("daemon://dead", e.to_string()); }
                }
                if let Some(w) = handle.get_webview_window("main") { let _ = w.show(); }
            });
            Ok(())
        })
        .build(tauri::generate_context!())
        .expect("error building Kaioken")
        .run(|handle, event| {
            if let tauri::RunEvent::ExitRequested { .. } = event { daemon::stop(handle); }
        });
}
```

`main.rs` is the standard six-liner with
`#![cfg_attr(not(debug_assertions), windows_subsystem = "windows")]` on top — omit
it and every release build on Windows opens a console window behind the app.

## 4.8 Sidecar naming and staging

Tauri appends the target triple to `externalBin` paths at bundle time, so the file
on disk **must already carry it**:

| Host | Required filename |
| --- | --- |
| Windows x64 | `binaries/kaioken-daemon-x86_64-pc-windows-msvc.exe` |
| macOS Apple Silicon | `binaries/kaioken-daemon-aarch64-apple-darwin` |
| macOS Intel | `binaries/kaioken-daemon-x86_64-apple-darwin` |
| Linux x64 | `binaries/kaioken-daemon-x86_64-unknown-linux-gnu` |

`scripts/build-sidecar.mjs` (spec in `07-build-release.md`) derives the triple from
`rustc -Vv | grep host`, maps it to `GOOS`/`GOARCH`, builds `../cli`, and copies
the binary under the right name. It runs from `predev` and `prebuild`, so a
developer never hand-copies a binary — and never ships a stale one.
